## Overview

This tool automates the processing and reconciliation of **Postilion ATM
Electronic Journal (EJ) files** - the raw transaction log files generated
by ATM terminals running on the Postilion payment switching platform.

Before this tool existed, operations teams manually searched through
unstructured `.dat` journal files to locate, extract, and verify individual
transaction records, a time-consuming process prone to human error.
This automation eliminated that manual effort entirely, saving significant
operational cost across a large ATM network.

---

## Business Problem

Every ATM terminal running on Postilion generates a daily Electronic Journal
`.dat` file, a continuous, unstructured log of every transaction event.
A single file may contain hundreds of transaction records mixed with system
events, card expiry alerts, failed attempts, and null entries.

Operations teams needed to:
- Extract only **successful transactions** (non-zero RRN) from these files
- Organise them by card **BIN** (issuing bank identifier) for routing
- **Reconcile** extracted records against the transaction ledger from the
  core banking system
- Generate a clean **PDF receipt** for each verified transaction

Doing this manually across multiple ATMs and multiple days was slow,
error-prone, and expensive in staff time.

## What the Tool Does

### Tool 1 - journal_split.py (Stage 1)

| Stage | What Happens |
|---|---|
| **1. File Discovery** | Walks `input_folder/` recursively, finds all `.dat` files across any subfolder structure |
| **2. Encoding Detection** | Detects file encoding automatically using `chardet` and converts to UTF-8 |
| **3. Transaction Splitting** | Splits each file at the `------------------` delimiter, each section is one transaction |
| **4. RRN Validation** | Checks the `<PostilionTran>` XML tag, skips any section with RRN = `000000000000` (null/failed) |
| **5. Metadata Extraction** | Extracts card BIN, RRN, date and time from the PostilionTran tag |
| **6. PDF Generation** | Saves each valid transaction as a PDF, named `BIN_RRN_Time_Date.pdf` |
| **7. BIN Organisation** | Groups PDFs into subfolders by card BIN inside `output_folder/` |
| **8. PDF Renaming** | Second pass resolves any unidentified PDFs by reading PostilionTran content from inside the PDF |
| **9. Audit Log** | Writes a complete processing log to `logs/journal_split_[timestamp].log` |

---

### Tool 2 - excel_check.py (Stage 2)

| Stage | What Happens |
|---|---|
| **1. PDF Scan** | Finds all PDFs in `output_folder/` |
| **2. Excel Load** | Reads all `.xlsx` files from `ExcelFiles/`, looks for `PAN` and `RETRIEVAL_REFERENCE_NR` columns |
| **3. Matching** | Combines card BIN (first 6 digits of PAN) with RRN to build a match key, checks each PDF filename |
| **4. Highlighting** | Highlights matched rows in **yellow** in the Excel file |
| **5. Cleanup** | Deletes PDFs with no corresponding Excel record |
| **6. Folder Cleanup** | Removes empty BIN subfolders after deletion |
| **7. Audit Log** | Writes a complete reconciliation log to `logs/excel_check_[timestamp].log` |

## How to Run

### Prerequisites
```bash
pip install -r requirements.txt
```

Or simply double-click the `.bat` files, they auto-install dependencies.

### Stage 1 - Process EJ Files
```bash
python journal_split.py
```
Or double-click `run_journal_split.bat`

### Stage 2 - Reconcile Against Excel
```bash
python excel_check.py
```
Or double-click `run_excel_check.bat`

Run Stage 1 first. Stage 2 requires the PDFs generated by Stage 1.

## Technical Notes

### RRN Validation
Postilion EJ files contain many zero-RRN entries, card expiry alerts,
null records, and system status messages. These are identified by
`RETRIEVAL_REFERENCE_NR = 000000000000` in the PostilionTran tag
and skipped automatically.

### Encoding Handling
Postilion journals are typically encoded in UTF-16-LE. The tool detects
encoding automatically using `chardet` and converts to UTF-8 before
processing, ensuring compatibility across different terminal configurations.

### Dynamic RRN Matching
The reconciliation engine uses dynamic-length key matching
(`BIN + RRN`) rather than fixed-length slicing, handling both 10-digit
and 12-digit RRN formats without configuration changes.

### Audit Trail
Every run generates a timestamped log file with full processing detail,
files found, transactions extracted, PDFs created, matches found, and
errors encountered. Essential for operational audit and compliance purposes.

## Professional Context

This tool was built to automate ATM transaction journal processing
across a multi-terminal Nigerian bank network running on the Postilion
payment switching platform. The manual process previously required
operations staff to individually search and extract transaction records
from unstructured journal files, a process that scaled poorly as the
ATM network grew.

The automation reduced processing time from hours of manual effort
to under few minutes per day, eliminating reconciliation errors
and creating a complete digital audit trail for every transaction processed.
